┄ The built-in operations the corpus uses, with the contracts it relies on.
┄ These are the `op` of the core calculus: extern controls with fixed contracts
┄ and no host state. The method form reaches them, so `values.push(x)` is
┄ `push(~values, x)`. `len`, `clone` and indexing are expressions.
┄
┄ A condition reads an `&~` parameter as its value at completion and `old` of
┄ it as its value at entry. Memory exhaustion is not an outcome, as in v1.

┄ Vectors
push(values: &~[t], value: t)
    ■ done ⇐ len(values) = len(old(values)) + 1
pop(values: &~[t])
    ■ item {value: t} ⇐ len(values) + 1 = len(old(values))
    ■ empty ⇐ len(old(values)) = 0 ∧ len(values) = 0
take(values: [t])
    ■ item {head: t, tail: [t]} ⇐ len(tail) + 1 = len(values)
    ■ empty ⇐ len(values) = 0

┄ Maps. Entries are ordered by key.
get(map: &k ⇀ v, key: &k)
    ■ found {value: &v ∈ map} │ missing
insert(map: &~k ⇀ v, key: k, value: v)
    ■ inserted ⇐ len(map) = len(old(map)) + 1
    ■ replaced {previous: v} ⇐ len(map) = len(old(map)) ∧ len(map) > 0
remove(map: &~k ⇀ v, key: &k)
    ■ removed {previous: v} │ missing
entry_at(map: &k ⇀ v, position: usize)
    ■ item {key: &k ∈ map, value: &v ∈ map, next: usize} │ finished

┄ Text. The functions are effect-free and have one result.
function trim(text: &string): string
emit(text: &string) ■ done uses console.write

┄ Checked arithmetic, for each integer type. An infix operator is used where
┄ the result is proved to fit, and one of these where it is not.
checked_add(a: i64, b: i64)
    ■ sum {value: i64} ⇐ value = a + b
    ■ overflow
checked_sub(a: i64, b: i64)
    ■ difference {value: i64} ⇐ value = a - b
    ■ overflow
checked_mul(a: i64, b: i64) ■ product {value: i64} │ overflow
checked_div(a: i64, b: i64) ⊢ b ≠ 0 ■ quotient {value: i64} │ overflow
